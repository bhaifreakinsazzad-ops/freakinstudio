# Project Brief — Freakin's Studio Creative Commerce OS

*Status snapshot, written on request. Short by design — see `docs/` for full detail.*

## Starting condition

The working directory was **completely empty** (no git repo, no files). The project brief referenced a legacy single-file HTML prototype (`freakin_s_studio_creative_commerce_os (6).html`) that was not in this folder — the user located it at `E:\Downloads\freakin_s_studio_creative_commerce_os (6).html`. That file is a 188KB browser-only React/Babel-CDN demo: no backend, no real database, no real auth, simulated payments, and a confirmed-missing `StudioAdminView` component.

## What's been built (Phase 0-1 "Foundation" of an 8-phase roadmap)

1. **Legacy preserved & audited** — byte-for-byte copy in `reference/legacy/`, full inventory in `docs/LEGACY_AUDIT.md`.
2. **App scaffold** — Next.js 16 + TypeScript + Tailwind 4 + shadcn/ui, dark brand theme ported from the legacy design.
3. **Database** — 8 SQL migrations (identity: profiles/organizations/members; catalog: service_categories/services/add_ons/service_add_ons), every table RLS-enabled with real policies.
4. **Real 60-service catalog** — extracted verbatim from the legacy file via a custom script (not fabricated), verified against the correct 7-category distribution (A=10...G=7=60).
5. **Auth** — real Supabase Auth (signup/login/dashboard), session middleware, role never client-supplied, role-escalation blocked at the RLS layer.
6. **Tests & verification** — `tsc`, `eslint`, `next build` all pass; 8/8 unit tests pass; an RLS/auth integration suite is written.
7. **Docs** — `README.md`, `CLAUDE.md` (project memory for future sessions), `docs/IMPLEMENTATION_STATUS.md`, `docs/DATABASE_SCHEMA.md`, `docs/DEVELOPMENT_PROGRESS.md`, `docs/REMAINING_WORK.md`.

6 commits on a clean git history.

## Live Supabase project — in progress

The user created a hosted Supabase project ("freakinstudio", ref `rvvwhlyqscxtwyqsvdbx`) and signed in to the dashboard in the browser pane.

- **Done**: All 8 migrations applied successfully to the live database (verified: 7 tables exist, every table has RLS policies). `.env.local` has the project URL and publishable (anon) key.
- **Blocked**: the project's **secret key** (service-role equivalent) could not be filled in automatically — the browser-automation permission classifier blocked revealing it, which is the correct behavior for a sensitive credential. It needs to be pasted in by hand: Supabase dashboard → Project Settings → API Keys → "Secret keys" → reveal → copy into `.env.local` / `.env.test` as `SUPABASE_SERVICE_ROLE_KEY`.
- **In progress, not finished**: seeding the live catalog tables with the real 60 services. A plain-SQL version of the seed (`supabase/seed/0001_seed_catalog.generated.sql`, generated by `scripts/generate-seed-sql.ts` so it can be pasted into the SQL editor without needing the secret key) was being loaded into the dashboard when work was paused. It has not been run yet.
